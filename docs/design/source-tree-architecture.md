# Potemkin source-tree architecture

This is the ownership map for the current TypeScript package. A module belongs
to one primary layer; cross-layer wiring is performed by the runtime or CLI
composition roots.

| Layer                                    | Owned modules                                                                                                                                                                                                                                                                             | Direction and responsibility                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Shared values and contracts              | `src/types.ts`, `src/errors.ts`, `src/ids/`, `src/schema/`, `src/model/`                                                                                                                                                                                                                  | Source-neutral JSON, diagnostics, identifiers, schema/value rules, deterministic data, patch operations, runtime contracts, model compilation, and the canonical runtime model. These modules do not import YAML, CEL, TypeScript discovery, HTTP, or Specmatic transport.                                                                                                                 |
| TypeScript authoring SDK                 | `src/authoring/`, `src/sdk/`                                                                                                                                                                                                                                                              | Typed builders, functional expressions, reducers, helpers, composition, and the `@PotemkinConfigure` registration contract. The SDK produces the canonical model and does not parse YAML or discover files.                                                                                                                                                                                |
| YAML definition and CEL                  | `src/dsl/`, `src/parser/yamlParser.ts`, `src/parser/configuredYaml.ts`, `src/parser/yamlCompiler.ts`, `src/parser/public.ts`                                                                                                                                                              | YAML schema/linking, CEL compilation, validation, and projection into the canonical model. This layer does not execute runtime commands.                                                                                                                                                                                                                                                   |
| TypeScript loader and configured loading | `src/parser/configuredTypeScript.ts`, `src/parser/typescriptLoader.ts`, `src/parser/typescriptFactoryScanner.ts`, `src/parser/typescriptDiscovery.ts`, `src/parser/typescriptFactorySyntax.ts`, `src/parser/typescriptModuleLoader.ts`, `src/parser/configured.ts`, `src/parser/mixed.ts` | Discovers and loads annotated factories, composes YAML and TypeScript models, and owns source-file watching/reload orchestration. It invokes the SDK; it does not implement runtime behavior.                                                                                                                                                                                              |
| Runtime model and engine                 | `src/model/`, `src/core/`, `src/runtime/`                                                                                                                                                                                                                                                 | `src/model/` owns source-neutral contracts, patch operations, builders, and compilation; `src/core/` and `src/runtime/` execute those models and coordinate storage, unit-of-work, policies, side effects, lifecycle, and injected ports. Runtime code does not branch on YAML versus TypeScript.                                                                                          |
| HTTP and external infrastructure         | `src/http/runtimeGateway.ts`, `src/http/runtimeObservation.ts`, `src/http/runtimeAdminRoutes.ts`, `src/http/runtimeGatewayTypes.ts`, `src/contract/`, `src/identity/`, `src/idempotency/`, `src/lifecycle/`, `src/observability/`, `src/webhooks/`                                        | Binds external protocols and operational services to runtime ports. The gateway composes request binding and route modules; observation and admin control-plane concerns have dedicated owners. These modules do not parse authoring formats or construct source-specific definitions.                                                                                                     |
| Composition roots and tooling            | `src/cli/`, `src/conformance/`, `src/index.ts`, `src/config.ts`                                                                                                                                                                                                                           | Select environment/process services, assemble the loader and runtime, expose public package surfaces, and run conformance/export tooling. JVM process control, binary acquisition, port allocation, exported-corpus seeding, and example-stack composition are owned by `src/conformance/`; tests and examples consume these modules but production conformance code does not import them. |
| Specmatic integration                    | `plugin/src/main/kotlin/`                                                                                                                                                                                                                                                                 | The JVM transport integration. It communicates with Potemkin through the documented HTTP transport contract and is not imported by the core runtime.                                                                                                                                                                                                                                       |

The intended flow is:

```text
YAML + CEL ───────┐
                  ├─> canonical model ─> runtime engine ─> HTTP / Specmatic
TypeScript SDK ─> loader ──────────────┘
```

The package metadata exposes the source-neutral model through the `./model`
subpath alongside the parser, SDK, runtime, and transport entry points; no
subpath is declared outside `exports`.

The architecture checks in `tests/unit/core/import-boundary.test.ts`,
`tests/unit/core/no-reexports.test.ts`,
`tests/unit/audit/dependencyBoundaries.test.ts`, and
`tests/unit/audit/sourceTree.test.ts` enforce the most important parts of this
map. Any exception must be a composition-root dependency or the intentional
static `@PotemkinConfigure` discovery contract.
